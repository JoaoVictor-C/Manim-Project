# 0062. Package layout: folders named for what the code does, and layers that are checked

- **Status:** Accepted
- **Date:** 2026-10-25
- **Deciders:** João Victor

## Context

`core/` had 53 modules in one folder, `ui/` 71, and the tests 89 and 129. Finding "the code that decides
what a layer's frames are" meant reading file names; the architecture page needed a 50-row table to say
which was which. The *dependencies* were already clean (nothing in `core/` imports `ui/`; Qt is used in
`ui/` and one `render/` file), but nothing said so except a paragraph of prose, and nothing stopped it
changing.

Measured on the code before the change: 147 modules, 539 imports between them, no static import cycle at the
level of the new packages, three lazy cycles that break module-level ones on purpose (`schema` reaching
`helpers`, `edits` reaching `adapter`, `plugins` reaching `adapter`).

## Decision

- **Group by what the code does, keep every file name.** `core/` becomes `model`, `editing`, `engine`,
  `sound`, `code`, `assist`, `exchange`; `ui/` becomes `style`, `session`, `shell`, `services`, `playback`,
  `deliver`, `canvas`, `timeline`, `panels`, `code`, `exchange`, `pages` (and `main_window.py` at its top);
  the helper processes move to `processes/`. No module was renamed, so a bare `schema.py` in a doc or a
  traceback still names one file ([the lookup](../dev/moved-modules.md) lists the old paths).
- **The layers are the dependency order that was already there, now written down and tested.** A package
  imports only from a lower rank (`tests/test_architecture.py`: `CORE_LAYERS`, `UI_LAYERS`), core and the
  processes never touch Qt, nothing below the window imports the window. Lazy (inside a function) and
  `TYPE_CHECKING` imports stay allowed: they are how this code base breaks a cycle. A grouping was chosen
  only if it kept the static package graph acyclic; five modules were placed by that rule rather than by
  name (`placement` and `tables` to the packages they depend on, `code_drag` and `editor_settings` to
  `session`, `render_activity` to `style`).
- **What other things were written against does not move:** `manim_studio.manim_scene` (exported scenes
  import it), `manim_studio.plugins` (the plugin API), `manim_studio.cli`, `python -m manim_studio`, and the
  logger names' root. The test lists them.
- **Files that are not code live in `manim_studio/data/`** (the built-in library, Manim's name table), found
  through one constant (`manim_studio.data.FOLDER`) instead of `Path(__file__)` arithmetic in two modules.
- **The tests mirror the code** (`tests/core/<area>/`, `tests/ui/<area>/`), the slice-by-slice walks are
  `tests/acceptance/`, and the process modules' tests are `tests/processes/`.
- **The move was a script, rehearsed on a copy, and proved.** Imports were rewritten from the syntax tree
  (exact), dotted names and paths in strings, comments and docs by name (longest first); then checked against
  the old tree (below). The script was thrown away; the checks that matter stayed as tests.

## Consequences

- Reading `ui/` shows the editor's parts; reading `core/` shows what needs no window. A new module has an
  obvious folder, and a test fails when an import points the wrong way.
- Every path in older ADRs, plans, the changelog and benchmarks was rewritten to the new place. Prose that
  names a *folder* in its old shape (`core/`) is still true as a package, not as a place for modules.
- Imports are longer by one segment (`from ..core.model import schema`). The price is paid once, in the
  import lines; nothing else in any file changed.
- The pytest IDs of every test changed with its path. Nothing else about the suite did: same tests, same
  results (see Evidence).

## Alternatives considered

- **Leave it flat, prefix the names (`core_*`).** Does not help `ui/`, and names then repeat their folder.
- **Rename modules that stutter (`core/code/code_cache.py`).** A rename also has to change every
  `code_cache.` use through the code and every doc that says `code_cache`; it adds risk for taste. The folder
  already says where; the unique file name stays greppable. Not now.
- **A compatibility layer that keeps the old import paths** (shims or `sys.modules` aliases). The only
  imports that must survive are the exported-scene and plugin ones, which did not move. Shims would hide
  every remaining stale import and keep two names for each module for ever.
- **Move the "no Qt" helpers of `ui/` (`gizmo`, `param_handles`, `graph_model`, `timeline/model`...) into
  `core/`.** True to their docstrings, but a behaviour-free rule today and a reason to touch 30 more files;
  they keep their package and could move with their own change.
- **A rope/LibCST refactoring session.** Both are good at moving a symbol; this was a pure module move with
  string and path references in hundreds of places, which neither tool does. They are also what the checks
  below make unnecessary to trust.

## Evidence

- Plan and the order of work: [../plans/p16-package-layout.md](../plans/p16-package-layout.md).
- Verified on a copy of the repository before the real one was touched, and again on the real one:
  - the **import graph** of the new tree equals the old one under the module renaming (every module has
    exactly the same imports, same kind: static, lazy, typing);
  - every moved file is **the same syntax tree** as before once imports and path strings are set aside;
  - every module **imports on its own** in a fresh process in both trees and exposes the same names;
  - the **same tests** pass (4330 collected passes before and after; the one failure is the zoom test, which
    fails on the untouched code as well), and the documentation links check passes;
  - the **wheel** builds and a clean environment with only the wheel installed passes the release check
    (`scripts/release_check.py`), which proves the data files are packaged;
  - a sample project renders **pixel-identically** before and after.
- Rules that now hold: [tests/test_architecture.py](../../tests/test_architecture.py).
- Where everything went: [../dev/moved-modules.md](../dev/moved-modules.md).
